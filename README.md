# FlashFX Landing Page

Marketing site for [FlashFX](https://flashfx.app), a browser-based motion graphics and video editor positioned as an alternative to After Effects and Premiere Pro. This repository is the public website only: the homepage, product and pricing pages, SEO comparison pages, legal pages and the in-page interactive demos. The editor itself is a separate application at [editor.flashfx.app](https://editor.flashfx.app); every call to action here links out to it. There is no backend, no API route and no data layer in this repo.

**Live site:** https://flashfx.app

## Features

**Pages (Next.js App Router, 22 routes)**

| Group | Routes |
|---|---|
| Product | `/`, `/features`, `/pricing`, `/download`, `/faq`, `/changelog` |
| SEO landing pages | `/after-effects-alternative`, `/free-motion-graphics-software`, `/lightweight-video-editor`, `/video-editing-software-for-beginners`, `/motion-graphics-software-for-youtube`, `/flashfx-vs-capcut-vs-davinci` |
| Company | `/about`, `/brand`, `/careers` |
| Legal | `/your-data` (server-rendered privacy notice), `/privacy`, `/terms`, `/refund-policy`, `/acceptable-use-policy` (Termly embeds) |
| Other | custom `not-found` page |

**Interactive demos instead of video embeds** (`components/demos/`)

- In-page recreations of the editor UI: keyframe timeline, clip (NLE) timeline, preset wall, media pool, shape tools, vector pen, clip playback, canvas studio, particle studio, camera rig, logo assembly, procedural morph and others.
- Every registered demo is loaded with `dynamic({ ssr: false })` through `components/demos/index.tsx`, so none of them land in the initial bundle.
- Remaining YouTube embeds create their iframe only when an IntersectionObserver reports the section approaching; server HTML contains no iframes.

**Motion system** (`lib/motion/`)

- `useAmbient()` is the single entry point for continuous animation. A framework-free governor caps concurrent ambient loops (default 6), pauses loops that are off screen, and honours `prefers-reduced-motion`.
- Device tiering demotes low-end and touch-primary devices to lighter animation.
- Shared `duration` / `loop` / `ease` / `reveal` tokens, plus `setLoopCap()` and `loopStats()` for diagnostics in the browser console.
- `BeamBorder` and `SectionSeam` (`components/ui/beam-border.tsx`) provide the animated edge and divider treatments.
- WebGL shader backgrounds (three.js, `@paper-design/shaders`) with a capped device pixel ratio (`lib/render-gate.ts`).

**SEO and structured data**

- Each `app/<slug>/page.tsx` is a server component that exports `Metadata`, declares its JSON-LD (`SoftwareApplication`, `FAQPage`, `BreadcrumbList`, `HowTo`, `ImageGallery`, and an `Organization`/`Person` entity graph) and renders an ordered list of sections.
- Sitemap, image sitemap and `robots.txt` are generated by `next-sitemap` on every build, with per-route priority and an explicit exclude list for the noindex legal pages.
- The screenshot gallery is described once in `lib/gallery-images.json` and reused by the carousel, the `ImageGallery` schema and the image sitemap.
- Shared social card image in `lib/seo.ts`.

**Editor deep links** (`lib/editor.ts`)

- `EDITOR_URL` and a typed `editorTemplate(id)` helper build `https://editor.flashfx.app/?template=<id>` links for the templates the editor is known to accept (`particles`, `galaxy`, `city-skyline`, `rocket-launch`, `forest`, `parallax`).

**Build guards** (`scripts/check-budgets.mjs`)

- Runs after every build and fails it if the homepage eager JavaScript exceeds 140 kB gzipped, any tracked file in `public/` exceeds 220 kB, or `public/` exceeds 3 MB in total.

## Getting started

### Prerequisites

- Node.js 16.14 or newer (required by Next.js 13.5.1) and npm
- git (the budget check in `postbuild` runs `git ls-files`)

### Download and install

```bash
git clone https://github.com/gabrielebolognese/FlashFX-landing-page.git
cd FlashFX-landing-page
npm install
```

### Configuration

No environment variables are required; nothing reads them at runtime. One optional build-time variable exists:

| Variable | Used by | Purpose |
|---|---|---|
| `SITE_URL` | `next-sitemap.config.js` | Overrides the default `https://flashfx.app` in the generated sitemap and `robots.txt` |

### Run in development

```bash
npm run dev
```

The dev server runs on http://localhost:3000.

## Build and deploy

```bash
npm run build
npm run start
```

`npm run build` runs `next build` and writes the output to `.next/`. The `postbuild` script then runs `next-sitemap` (regenerating `public/sitemap.xml`, `public/sitemap-0.xml` and `public/robots.txt`) followed by `node scripts/check-budgets.mjs`, which exits non-zero if a budget is breached. `npm run start` serves the production build.

Deployment is on Netlify, configured in `netlify.toml`: build command `npm run build`, publish directory `.next`, with the `@netlify/plugin-nextjs` plugin. The build command must stay `npm run build`; calling the `next` binary directly skips `postbuild`, so the sitemap and the budget check would not run.

## Usage

| Command | What it does |
|---|---|
| `npm run dev` | Start the Next.js dev server |
| `npm run build` | Production build, then sitemap generation and the budget check (`postbuild`) |
| `npm run start` | Serve the production build |
| `npm run lint` | ESLint with `next/core-web-vitals` |
| `npm run typecheck` | `tsc --noEmit` |

`next.config.js` sets `eslint.ignoreDuringBuilds: true`, so a passing build does not mean lint passes. Run `npm run lint` and `npm run typecheck` explicitly before shipping. There are no tests and no test runner configured.

Common edits:

- **Add a page:** create `app/<slug>/page.tsx` (metadata, JSON-LD, section list) and a matching `components/sections/<slug>/` folder. The route is picked up by the sitemap automatically; add an entry to `ROUTES` in `next-sitemap.config.js` only if it needs a non-default priority.
- **Add a changelog entry:** prepend a release to `components/sections/changelog/changelogData.ts`.
- **Add a gallery screenshot:** add the WebP to `public/lookslike/` and describe it in `lib/gallery-images.json`.
- **Add a demo:** register it in `components/demos/index.tsx` rather than importing it directly.

### Conventions that break silently

- **JSON-LD uses a plain `<script>` tag, never `next/script`.** `next/script` defers the tag until after hydration, so it never reaches the server-rendered HTML.
- **The entity graph `@id` and `sameAs` values are string-exact.** `/` and `/about` emit the same `Organization`/`Person` graph, which must match the one on gabrielebolognese.blog. Do not normalise, reorder or re-slash the URLs.
- **The footer author link carries `rel="me"`.** Keep it.
- **No rating markup.** `aggregateRating`, `Review` and star ratings are deliberately absent.
- **FAQ copy is duplicated by design** between the `faqSchema` literal in a page and the visible FAQ data. Update both.
- **`h1` has a global gradient** with a transparent text fill (`app/globals.css`), so `text-*` colour classes on an `h1` are invisible.
- **Images are unoptimised** (`images: { unoptimized: true }`); `next/image` does layout only and image weight is managed by hand, within the budgets above.
- **No raw `repeat: Infinity`.** Continuous animation goes through `useAmbient()`.
- **Design tokens** live as CSS custom properties in `app/globals.css` and are exposed as `fx-*` Tailwind utilities. `components/ui/` holds both shadcn/ui primitives (`button.tsx`, `card.tsx`) and bespoke `fx-*` components that also export `Button` and `Card`; check the import path.

## Project structure

```
app/                      Routes: one server-component page.tsx per slug, layout.tsx, globals.css
components/sections/      Page sections, grouped by route, with sibling .ts data files
components/demos/         Interactive in-page recreations of the editor
components/ui/            shadcn/ui primitives, fx-* components, shader and border effects
components/layout/        Footer
components/Navbar.tsx     Navigation, including the mobile menu
components/PageLoader.tsx CSS-only splash overlay
lib/motion/               Ambient-loop governor, device tier, pointer, timing tokens
lib/                      editor.ts (deep links), seo.ts, gallery.ts, render-gate.ts, viewport.ts, utils.ts
content/devlog.md         Development log
public/                   Static assets: screenshots, template and browser images, icons
scripts/check-budgets.mjs Post-build size budgets
next-sitemap.config.js    Sitemap, image sitemap and robots.txt configuration
netlify.toml              Netlify build settings
```

## Tech stack

- Next.js 13.5.1 (App Router), React 18.2, TypeScript 5.2 (strict)
- Tailwind CSS 3.3 with `tailwindcss-animate`, shadcn/ui on Radix UI primitives, lucide-react icons
- framer-motion for animation; three.js and `@paper-design/shaders` for WebGL backgrounds
- `next/font/google`: Inter (headings), Outfit (body and UI), JetBrains Mono (figures)
- `next-sitemap` for sitemap and robots generation
- Termly embeds for four of the legal pages
- Netlify with `@netlify/plugin-nextjs`

`@supabase/supabase-js` is listed in `package.json` but is not used by any code in the repository.
